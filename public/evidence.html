Public proof maintenance

Portfolio evidence should expire loudly.

A scheduled audit checks whether the public projects, repositories, releases, policies, commit references, and signing or provenance disclosures behind this portfolio are still reviewable.

Evidence boundary

A clean report confirms only the configured public surfaces at the recorded time. It is not a vulnerability scan, penetration test, cryptographic certification, or guarantee that a project is secure.

Current reports and source data

Deployments refresh the public Markdown and JSON snapshots. A weekly GitHub Actions run produces a timestamped workflow artifact and job summary without silently committing generated results.

Checks performed

  • Public product, repository, release, package, policy, and artifact links.
  • Repository default-branch commits against the portfolio's last reviewed commit, where one is recorded.
  • The registry review and artifact manifest remain inside their 45-day review windows.
  • SECURITY.md in the repository root, .github, or docs.
  • Unsigned, checksum-only, or attested artifacts have an explicit public disclosure; attested or signed states must link to verification evidence.
  • Local artifact paths and SHA-256 values still match the manifest.

Safe report contents

  • Public project identifiers and sanitized HTTPS URLs.
  • HTTP status classes and public Git commit prefixes.
  • Configured public content markers are compared in memory but never copied into reports.
  • Missing policy, stale reference, and artifact disclosure findings.
  • No response bodies, headers, tokens, credentials, query strings, fragments, cookies, or private repository data.

How to read findings

LevelMeaningExpected response
ErrorA reviewed commit moved, a required link or policy failed, a review window expired, or a local hash, manifest rule, or trust disclosure failed.Block publication or correct the evidence before treating the claim as current.
WarningA recommended policy is missing or a service limited automated validation.Review the project and refresh the claim or document a time-bounded accepted risk.
CleanThe configured checks passed at the recorded time.Keep the scheduled check running and retain project-specific security review.

Artifact trust is explicit

  • Portfolio resumeUnsigned. The published SHA-256 checksum detects a changed file but is not signer identity.
  • RMM HunterCurrent Windows beta builds are unsigned unless a release page states otherwise. The published-release ceremony checks asset digests, checksums, tag provenance, update metadata, and actual Authenticode state.
  • AES Secure VaultChecksums, SBOMs, and attestations provide provenance evidence. They are not operating-system code signing or cryptographic certification.

Detailed wording and canonical links live in the security policy and artifact manifest.

Known review item: Cloudflare DNS Action does not currently publish a repository SECURITY.md. That project is outside this remediation slice. The accepted-risk warning stays visible and expires on 31 August 2026; after expiry, the checker fails until the gap or waiver is reviewed.

Reproduce the checker

Run the deterministic offline tests and then the live public check:

node --test tests/evidence_freshness.test.js
node tools/check_evidence_freshness.js

The offline fixtures make stale-commit, missing-policy, broken-link, unsigned-disclosure, and report-redaction behaviour testable without a network. The live command uses only public endpoints and may report a warning when a service rate-limits automated checks. Scheduled runs fail on errors and actionable warnings, while an unexpired accepted-risk warning remains visible without failing the run.

Live requests are limited to the documented GitHub, PyPI, and portfolio host allowlist. Redirects are revalidated, private address ranges are rejected, and the checker still relies on public DNS for those approved hostnames.
