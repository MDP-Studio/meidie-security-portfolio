Current reports and source data

Deployments refresh the public Markdown and JSON snapshots. A weekly GitHub Actions run produces a timestamped workflow artifact and job summary without silently committing generated results.

Latest Markdown reportHuman-readable ↗ Machine-readable reportStructured JSON ↗ Evidence registryReviewed sources ↗ Scheduled runsGitHub Actions ↗

A clean report confirms only the configured public surfaces at the recorded time. It is not a vulnerability scan, penetration test, cryptographic certification, or guarantee that a project is secure.

Checks performed

  • Public product, repository, release, package, policy, and artifact links.
  • Repository default-branch commits against the portfolio’s last reviewed commit, where one is recorded.
  • The registry review and artifact manifest remain inside their 45-day review windows.
  • SECURITY.md in the repository root, .github, or docs.
  • Unsigned, checksum-only, or attested artifacts have an explicit public disclosure. Attested or signed states must link to verification evidence.
  • Local artifact paths and SHA-256 values still match the manifest.

Safe report contents

  • Public project identifiers and sanitized HTTPS URLs.
  • HTTP status classes and public Git commit prefixes.
  • Configured public content markers are compared in memory but never copied into reports.
  • Missing-policy, stale-reference, and artifact-disclosure findings.
  • No response bodies, headers, tokens, credentials, query strings, fragments, cookies, or private repository data.

How to read findings

Reproduce the checker

Run the deterministic offline tests, then the live public check:

node --test tests/evidence_freshness.test.js
node tools/check_evidence_freshness.js

The offline fixtures make stale-commit, missing-policy, broken-link, unsigned-disclosure, and report-redaction behaviour testable without a network. The live command uses only public endpoints and may report a warning when a service rate-limits automated checks.

Live requests are limited to the documented GitHub, PyPI, and portfolio host allowlist. Redirects are revalidated, private address ranges are rejected, and the checker still relies on public DNS for those approved hostnames.
